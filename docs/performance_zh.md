选择计算路径，理解内存开销，并按测量条件解读基准。模型和调用示例放在各专题指南。

## 选择计算路径

| 使用场景 | 建议路径 | 仍需承担的成本 |
| --- | --- | --- |
| 大物种池、低占据率 | CSC `CommunityData`，自动连接树 | 原输入/树的校验和准备 |
| 相同数据上反复计算 PD/PE/beta | `prepare_community` | 保存分支集合，每次分配结果 |
| 重复计算 `comdist` / `comdistnt` | `prepare_community_distances`，已知时固定 `pairs` | 一次准备及常驻工作区 |
| 同时需要 PSV、PSE、PSC | `psd` | 开启时仍计算完整物种池方差 |
| 只需要 Rao 汇总 | `raoD(...; pairwise=false)` | 各群落及合并群落计算 |
| 少量 Expected PD 丰富度 | `expected_pd(...; richness=values)` | 线性树准备 |
| 后验树不确定性 | `TreeStream` 上的 `mean_dist(data, trees)` | 逐树匹配/分支集合及请求输出 |
| 少量群落比较 | 支持的 `pairs` 接口 | 校验全部输入；beta SES 仍随机化完整群落 |

稠密输入仍需扫描全部单元格。即使输入与工作区稀疏，完整群落对输出仍有平方空间下界。

## 运行环境

EvoKits 先加载 MKL 以选择 BLAS 后端。Julia 线程和 BLAS 线程分别设置；下列测量均各用一个线程。增加 BLAS 线程并不直接加速树遍历内核。

## 性能基准

下表摘录已有本地测量，并非每次发布重新运行的全面基准。除非另有说明：Julia 1.12.7、单 Julia/BLAS 线程、串行、预热后三次中位数；公开调用包含校验、准备和输出分配，不含输入构造。部分记录同时注明 Intel i5-12400。树形、占据率、枝长尺度、输出范围和硬件均影响结果，自动路径不保证所有数据都提速。

| 数量 | 含义 |
| --- | --- |
| 累计分配 | 调用期间分配的字节，包含临时对象 |
| 保留量 | `Base.summarysize` 测得的结果/上下文可达对象，不含未引用输入 |
| 数组载荷 | 理论数组字节数，不含对象头和分配器开销 |
| 进程峰值 RSS | 整个进程的最高占用，包含加载、JIT 及此前工作 |

MB/GB 均为十进制。除均值累计的独立进程实验外，下表未测 RSS。内部已准备内核的耗时不能当作公开调用耗时。

在单线程 Julia 中可运行以下小型测量：

```julia
using EvoKits, LinearAlgebra, Statistics
BLAS.set_num_threads(1)
tree = mktempdir() do dir
    path = joinpath(dir, "star.nwk")
    write_tree(path, "(" * join(("sp_$i:1" for i in 1:128), ",") * ");")
    read_tree(path)
end
call() = expected_pd(tree; richness = [10, 50, 100], upper_bound = false)
call()                         # 编译与预热
samples = map(1:3) do _
    GC.gc()                    # 在计时调用之外
    @timed call()
end
median(s.time for s in samples)
median(s.bytes for s in samples)
Base.summarysize(call())       # 结果保留量，不是进程峰值
```

以下 n 为群落数，p 为 tips，e 为树节点，q 为正值群落—物种记录，r 为群落丰富度，v 为工作树节点；CSC 的 `nnz` 包含存储的零项。其余符号在各节说明。

## 后验树输入

`read_trees` 扫描一遍，仅保留当前记录/树、来源路径和当前 NEXUS 翻译表。`tree_sampler` 扫描两遍，仅解析抽中记录，保存抽样元数据与抽中树；字典表示的局部 Fisher–Yates 抽样避免建立总体大小的索引数组，重复记录只解析一次再复制。

`CompactTree` 用迭代后序构建，时间/存储线性，保留孩子顺序。真实 65,536-tip 左右梳状树完整 `read_tree` 为 136/126 ms、累计分配 119.73/116.18 MB、每棵结果保留 17.89 MB，包含读取、解析和转换。深树输入可用不代表全部下游树操作均为迭代实现。

## 后验 beta 直接累计

`mean_dist(data, trees)` 只准备一次群落记录与请求，每棵树仅计算一个 beta 成分，并更新缩放补偿均值。逐树重新匹配标签和构建分支集合，复用缓冲容量，避免为每棵树构造三组成分结果。

至少 128 群落的完整输出用稀疏分支—群落成员关系，将共享枝长累计到 `n × min(n, block_size)` 列块。共享工作量与 `sum(d*(d+1)/2)` 及平方单元格计算相关。小型输出和指定对合并有序分支集合；近相消时直接累加独有分支。深梳状树可能保存很长且高度共享的分支集合，完整矩阵仍昂贵。

b 条群落—分支成员关系、k 个请求时，指定对辅助存储 `O(e+p+q+b+n+k)`；完整输出为 `O(e+p+q+b+n²+n*min(n,block_size))`。减小列块只控制临时空间，最终均值/次数矩阵仍为平方。

### 均值累计存储

两个均值入口均保留完整 sums/counts 作为最终输出，scales/corrections 使用压缩下三角；收尾原地归一化并镜像。64 位 Int/Float64 下数组载荷 `24n²+8n` 字节，返回均值/次数本身 `16n²` 字节；6,000 群落分别约 0.864 GB 和 0.576 GB。指定对使用四个一维数组。

2,048 群落、八次输入的公开调用记录：

| 输入 | 耗时 | 累计分配 |
| --- | ---: | ---: |
| 稠密距离矩阵 | 472 ms | 103.03 MB |
| 惰性距离矩阵 | 586 ms | 103.03 MB |
| 后验 beta 直接累计；256-tip 星形、每群落一个物种、block=64 | 236 ms | 102.47 MB |

独立进程实验为 4,096 群落、两次惰性输入、三个新进程及相同加载/预热：中位累计分配 404.95 MB，进程峰值 RSS 947.79 MB，包含此前约 551 MB 的加载/JIT 峰值；不能用数组载荷公式推断这些总量。

## 群落长表导出

q 个正值时，`community_longtable` 对 CSC 为 `O(nnz+n+p)` 工作，稠密输入为 `O(n*p+n+p)`；输出及临时空间 `O(q+n+p)`。不稠密化、不按丰度展开，空输入也复制完整标签域。存储回归阈值不等于耗时或峰值测量。

## 群落间系统发育距离

`comdist` 使用后序/前序目标权重和距离累计，`comdistnt` 传播两个不同目标身份。原始分支段与稳定兄弟累计保留长共有枝下的短路径；丰度先缩放再归一化，避免求和溢出。

CSC 准备 `O(nnz+p+n+e)`；稠密另扫描 n*p。自动连接树对 u 个观测物种最多保留 `2u-1` 节点，累加原边并去掉其 LCA 以上共有根枝；密集占据率保留整树。策略是内部启发式。

准备后 t 个必要目标的完整输出为 `O(t*(v+q)+n²)`；k 个请求的排序/调度 `O(k log k)`，计算 `O(t*v+P+k)`，P 为独特双向查询中源群落丰富度之和。全部输入仍校验，仅保留有效请求端点。

### 群落距离预处理复用

`CommunityDistanceContext` 保存 `O(n+qR+v+k)` 的记录、拓扑、调度及两种权重/距离工作区，qR 为保留记录数；独立快照不持有原矩阵/树。固定请求缓存调度，还可能进一步缩小拓扑；完整上下文更换请求时复用拓扑，但重新调度。锁使共享工作区的调用串行，每个结果拥有新数组。

| 完整 `comdistnt` | 1.17 ms | 0.227 ms | 1.73 MB | 0.0329 MB |

## Rao 多样性分解

RaoD 复用稀疏记录、距离工作区和自动连接树；先在原树校验和按原丰度合并。s 个非空群落的准备为 `O(nnz+p+n+e)`，辅助空间 `O(q+p+n+e)`；准备后完整计算 `O(s*(v+q)+v+q+n²)`，汇总 `O(s*v+q+v+n)`。完整输出两份 n×n 矩阵，汇总输出随 n 线性增长；高覆盖率保留整树。

32 群落、每群落三物种、65,536-tip 超度量树、CSC、丰度加权、汇总模式的公开调用记录：

| 树形 | 耗时 | 累计分配 |
| --- | ---: | ---: |
| 平衡 | 1.14 ms | 3.215 MB |
| 梳状 | 1.06 ms | 3.215 MB |
| 星形 | 0.592 ms | 2.398 MB |

平衡样例从 131,071 压至 191 节点。6,000 群落、64-tip 星形的完整/汇总耗时 579/3.39 ms，累计分配 578.02/2.025 MB，结果保留 576.048/0.0482 MB；计时不含造树和解析。

## 解析多样性矩

PSV/PSR/PSE/PSC/PSD 直接由树统计量计算，无完整 VCV/相关矩阵或群落子矩阵。中心化矩、相关性亏量和原始路径保留长枝下的细小差异。稀疏准备随 `nnz+p+n+e` 线性增长，稠密准备扫描 n*p。

Expected PD 使用子树累计和按后代数缓存的概率。m 个请求点的准备 `O(p+e)`、计算 `O(m*e)`、存储 `O(p+e+m)`，默认完整曲线 `O(p*e)`。空/全 p 请求校验后 `O(e+m)` 返回，不准备树工作区；对数尾项保留概率下溢后仍可表示的方差。精确和上界模式空间阶相同。

4,096-tip 单位枝长树、精确方差：完整曲线后取点与 `richness=[10,50,100]` 两条可选路径的记录：

| 树形 | 完整曲线后取点 | 指定点 | 完整累计分配 | 指定累计分配 |
| --- | ---: | ---: | ---: | ---: |
| 平衡 | 126.22 ms | 0.297 ms | 0.396 MB | 0.297 MB |
| 梳状 | 344.25 ms | 0.412 ms | 0.686 MB | 0.587 MB |
| 星形 | 58.02 ms | 0.105 ms | 0.280 MB | 0.182 MB |

完整曲线一列测自紧邻的上一版完整曲线实现，默认数值结果精确一致。65,536-tip 平衡/梳状/星形三点为 4.24/7.91/1.70 ms、累计分配 4.72/9.62/2.88 MB，各结果保留 224 B；未测大树完整曲线。

### PSV/PSR 连接树

稀疏群落用线性空间的重链/分段索引，在 v 节点工作树中以 `O(r log r+r log² v)` 提取至多 `2r-1` 节点，以 `O(r)` 求矩；密集群落采用 `O(v+r)` 顺序路径。完整物种池方差每次在**包含未观测物种的完整原树**准备一次，另需 `O(e+p)` 工作/存储。

100,000-tip 单位枝长树、64 个 CSC 群落、每群落三物种、相关性缩放的公开 PSV：

| 树形 | 不含方差耗时 | 含方差耗时 | 不含/含方差累计分配 |
| --- | ---: | ---: | ---: |
| 平衡 | 5.61 ms | 18.75 ms | 8.19 / 18.59 MB |
| 梳状 | 6.83 ms | 22.12 ms | 8.19 / 18.59 MB |
| 星形 | 2.94 ms | 9.29 ms | 4.49 / 10.09 MB |

小群落树仍不能消除完整池方差成本，开启方差时连接树准备可能增加分配。独立调用重新准备，内部已准备内核不是公开复用 API。

### PSE、PSC 与 PSD 共用计算

PSE 累计跨子树加权差异，PSC 传播两个不同目标身份。压缩路径保存原高度和有序仿射变换，维持相关性/原始协方差定义；极少数下溢丰度贡献用 BigFloat 树遍历。

PSD 为 PSV/PSE/PSC 共用一棵群落树，由 PSV 得 PSR，等丰度时复用 PSV 得 PSE；提取与计算复杂度同上，开启方差时仍用原物种池。

同一 100,000-tip/64 群落设置、丰度 `[1,2,3]`、相关性缩放：

| 树形 | PSE 耗时/累计分配 | PSC 耗时/累计分配 | 含方差 PSD 耗时/累计分配 |
| --- | ---: | ---: | ---: |
| 平衡 | 5.69 ms / 8.20 MB | 5.99 ms / 8.20 MB | 20.2 ms / 18.63 MB |
| 梳状 | 6.62 ms / 8.21 MB | 6.44 ms / 8.20 MB | 22.0 ms / 18.64 MB |
| 星形 | 2.78 ms / 4.50 MB | 3.51 ms / 4.50 MB | 9.71 ms / 10.13 MB |

平衡树不含方差 PSD 为 6.31 ms / 8.23 MB。密集群落保留顺序遍历，不能将稀疏收益外推到全占据率。

## PD 变体与 bootstrap

`pd_calc` 使用稀疏记录和后代计数。稀疏 r-tip 群落复用线性路径/群落索引，工作 `O(r log r+r log² e)`；密集群落 `O(e+r)`，TIP 直接求 r 条末端边。对齐 CSC 准备 `O(nnz+p+n+e)`，每次公开调用自行准备索引。

bootstrap 每个非空抽样仍扫描 p 个概率，有限堆保留最优 r 个键或最差 p−r 个键的补集；堆空间 `O(min(r,p-r))`，另有选中 tips/可选位标记。抽样 `O(p*(1+log(max(1,min(r,p-r)))))`，最优键路径另排序所选键。不构造稠密随机群落，返回重复值仍需 `O(n*reps)` 空间；保留 RNG 消耗及稳定并列规则。

10,000-tip 平衡树、16 群落、每群落三物种、11 次 bootstrap、均匀权重；树输入仅一个群落：

| 调用 | 耗时 | 累计分配 |
| --- | ---: | ---: |
| `pd_calc`，TBL | 0.967 ms | 2.48 MB |
| 群落 `pd_bootstrap` | 13.0 ms | 2.96 MB |
| 树 `pd_bootstrap` | 2.22 ms | 2.57 MB |

## 零模型

群落内 SES 和 beta SES 保留一次随机群落及可复用物种/树工作区，在线累计均值和样本 SD。beta `pairs` 减少端点分支集合和输出，但每次仍随机化完整输入以保留模型边际和物种池。交换次数和重复数仍是计算成本，稀疏存储不意味着常数时间随机化。[模型定义](null_models_zh.md)单独说明。

## 树距离精度

根深度相减的相对损失可控时直接使用，否则经按需加权祖先跳跃累加原始分支。索引后查询 `O(log e)`，祖先/加权跳跃索引需 `O(e log e)` 空间；它与群落内核的线性工作区分别适用。完整 tip 对输出相对请求 tip 数仍为平方。

## 多群落分类 beta

`beta_multi` 由物种占据数计算共享计数和，再排序丰富度求两两最小/最大值之和；Int128 计数仅在最终比值时转浮点，不创建群落对矩阵。选择 m 个群落，CSC 工作 `O(nnz+p+n+m log m)`、辅助空间 `O(n+p)`；稠密 `O(n*p+m log m)`，未选行也校验。

## 多群落系统发育 beta

`phylobeta_multi` 复用分支集合和已排序含根 PD，以非负 Int128 占据/秩系数先消除共有分支再乘枝长；近等 PD 或极端尺度可触发 2304-bit 回退，输出仍为 Float64。b 条所选群落—分支记录、m 群落时，收集分支后工作 `O(b+e+m log m)`、辅助空间 `O(e+m)`。`CommunityContext` 复用分支集合，直接调用先校验全部输入；两条路径均不建立稠密群落—分支或群落对矩阵。多群落存储检查提供分配阈值，不作耗时或 RSS 结论。

## 分区与排序

六种单调连接法使用 `O(n²)` 最近邻链，质心/中位连接缓存行最小值，最坏时间为 `O(n³)`。聚类使用 `n*(n-1)/2` 个 Float64 的压缩三角；完整输入和区域输出仍为平方空间。`PhyloregionContext` 保留一份三角，准备时另用一份临时三角。仅切树为 `O(n)`，区域汇总仍需遍历群落对；连接法评估不建立完整 cophenetic 矩阵，全部切分的离差评分遍历每个群落对一次，额外存储 `O(n)`。

固定 k 个区域的 GoM 使用 `O(nnz+(n+p)*k)` CSC 工作存储，不建立稠密群落或 nnz×k 责任矩阵。指示物种按目标区域使用物种向量，不建立物种×区域×区域张量。

NMDS 保存平方级群落对状态，不保留群落对×迭代历史。默认 PCoA 初始化另需立方级计算；`init=:random` 可避免该初始化，迭代及多起点仍有成本。更换初始化会改变优化路径，应检查 stress 和收敛诊断。

## 指标数值分级

精确 Jenks 在 m 个不同排序值上进行保留重复次数权重的动态规划：k 类耗时 `O(k*m²)`，工作空间 `O(k*m)`；`max_work=50_000_000` 显式限制计算量。平移缩放和 Welford 区间方差避免原始平方和相消。等距和分位数方法具有不同统计定义，详见[分级规则](conservation_zh.md#指标数值分级)。
